# 校园空间实施与验收计划

用户要求「实现校园空间，自己先规划，然后实现所有功能」。本计划定义本次完整交付范围，随后直接实施，无需重复确认。基于已发布的 `7a88d107`，工作分支为 `feature/campus-space`；保留现有聊天、文章、群组、账户、通知和蓝色/中性色界面。

## 产品规则

1. 登录用户浏览、搜索、分页查看学校目录和学校简介；站点管理员创建/启停学校、设置是否预审动态，初始创建者成为该校管理员。学校管理员只拥有本校权限。
2. 用户申请本校学生身份，填写姓名、学号、院系、入学年份及简短说明；申请详情仅本人和有权审核者可见。管理员人工核验、通过/拒绝，申请人查看理由、撤回待审核申请、拒绝后重提。界面明确这是站内人工审核，不承诺学校官方学籍系统认证，不采集身份证或证件照片。
3. 同一用户可拥有多个经过独立审核的学校成员身份。只允许每校一条待审申请；审核不能自审或覆盖已处理申请。成员退出/暂停、管理员降级和学校停用立即影响后续读取、写入、图片访问及通知交付。被暂停用户不能自行重新申请绕过管理。
4. 校园动态与公开文章分表，默认仅本校有效认证成员可读。支持文字、最多六张图片，分类 GENERAL/STUDY/LIFE/LOST_FOUND/ANNOUNCEMENT；公告仅管理员发布。图片需鉴权读取，不放在公开静态目录。
5. 完成草稿、提交、发布、拒绝、编辑重审、删除流程。学校默认预审，管理员可关闭预审。编辑和审核带版本校验；旧审核/编辑不得重新发布新版本或已移除内容。草稿/待审/拒绝仅作者和本校管理员可查看。
6. 学校动态支持标题/正文字面搜索、分类、最新/热门排序、服务端分页，支持我的发布、我的收藏。点赞及收藏采用幂等 PUT/DELETE；评论和回复分页，作者/管理员可删除，回复不得跨动态。退出学校后收藏不能成为访问旁路。
7. 成员可举报可见动态；本校管理员分页处理举报，实际移除内容或驳回，并记录理由。管理员可审核动态、置顶已发布动态、管理成员、查看操作审计；站点管理员可任命/撤销学校管理员。学校管理员不得提升自己、处理自己的认证或越权管理另一学校。
8. 认证、审核、点赞、评论/回复使用现有通知入口。通知存储与业务事务一致，提交后推送；通知不包含正文或认证资料。校园动态通知的列表、计数、推送和点击均执行当前权限判断。失败的推送可通过持久通知列表恢复。

## 技术边界

- 继续 Spring Boot/MyBatis/JDBC + Vue/Pinia 模块化单体，不引入新运行依赖。
- 新的 V006 迁移创建校园表；已发布 V001–V005 内容和校验和保持不变。空库、V005 升级、重复执行、失败恢复均须验证。
- 新接口统一 `/api/campus`，使用 `ApiResponse` (`code:0`)，列表为 `{list,total,page,size}`，从 page=0 开始，size 默认20、上限100；搜索最多100字符，结果窗口最多10000。
- 身份来自 `@Userid`；站点 ADMIN 仍来自启用用户的持久化 `user.type`，校内角色来自独立成员记录。禁止请求体决定操作人或角色。
- 新校园动态不写入原 articles、article_comment、article_like、用户文章积分/公开统计或全站文章搜索。复用认证、通知基础设施和 UI 规范。
- 使用当前权限服务集中判定学校、成员、动态与媒体读取；变更权限的写入采用一致事务/锁顺序。分页、缓存和前端迟到响应遵循已修复的会话代次约束。
- 每张图片最大5MB、解码尺寸不超过4096×4096且不超过1600万像素；只接受可解码 PNG/JPEG/GIF 并重新编码 PNG。服务端生成名称，限制未关联上传，删除/过期孤立文件可回收。
- 所有管理动作实际修改业务状态并追加审计，不能用日志输出或占位按钮代替功能。

## 验收场景

| 场景 | 必须达到的结果 |
| --- | --- |
| 创建学校 → 申请 → 审核 → 访问校园 | UI 和实际 HTTP 可完整完成，待审/拒绝用户不能读取动态或图片 |
| 另一学校、停用学校、退出/暂停成员 | 动态、详情、搜索/总数、评论、收藏、图片、通知均无权限旁路 |
| 申请重复/并发审核/管理员降级 | 唯一待审、唯一有效处理结果，旧权限/旧版本不会生效 |
| 图文草稿 → 提交 → 审核发布 → 编辑重审 | 状态和版本一致，旧审核不能发布新正文，失败提交保留用户输入 |
| 幂等点赞/收藏、评论回复/删除 | 重放不重复计数，跨动态父评论被拒绝，删除不会泄露旧正文 |
| 举报 → 管理员处理 | 内容实际从普通读取/搜索/图片访问中移除，操作可审计 |
| 恶意/超限上传、他人图片关联、退出后旧图片地址 | 拒绝或返回无权限，无公开静态图片旁路；孤立图片可回收 |
| A 请求迟到、B 登录或切换学校 | 不污染新会话/学校，不发生陈旧跳转或清理新状态 |
| V005 升级、空库、旧业务回归 | 新校园功能可用，原有业务测试及前后端合同继续通过 |
| 浏览器完整校园旅程 | 实际创建/审核/发帖/评论/通知/管理交互通过，控制台和接口无未处理异常 |

该范围交付一个可运行、可管理的校园社区。学校官方 SSO/教务系统连接需要实际服务协议和凭据，不伪造验证结果；校务缴费、课程选课等不属于本校园社区的既有需求。
