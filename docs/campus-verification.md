## 迁移与安装

V006创建10张校园表。V001–V005的注册项、资源路径及规范化内容均与发布基线逐项比较保持一致。V006注册校验和为 `81fdf0e31f08ad6beee3fce9169273480aad0268518c6e63e27c977d723a4a63`；它是迁移器的资源路径/内容组合校验和，不是单个SQL文件的原始SHA-256。

完整迁移套件覆盖空库、真实旧结构升级、V005升级、失败后显式恢复和只读生产校验，也验证现有校园表列长度/类型不兼容时拒绝迁移。开发期曾因 MySQL 返回的生成表达式含转义引号被校验器误拒，修正解析后使用相同V006校验和显式恢复；没有删除失败账本或更改旧迁移来绕过校验。

按照[迁移说明](schema-migrations.md)先应用迁移，再以站点管理员创建学校。配置私有持久 `CAMPUS_MEDIA_DIRECTORY` 并与MySQL一同备份。校园认证为站内人工审核；没有默认学校、默认管理员密码或自动认证用户。

## 干净候选版本与复现

配置[专用审计环境](operations.md#local-verification-services)后，在干净的功能分支运行：

```powershell
python scripts/release_gate.py --offline --chrome "C:/Program Files/Google/Chrome/Application/chrome.exe"
```

没有完整依赖缓存时去掉 `--offline`。门禁在两份独立源码副本上构建，第一份执行全部后端/前端测试和58项真实运行断言，第二份构建用于对比；缺失校园集成套件、任何JUnit跳过或运行断言缺失都失败。测试和运行使用专用服务，不能并行启动另一个访问相同测试数据库的应用。

以该次输出的 `.local/release/<run>/public/release-manifest.json` 为最终候选证据：它绑定确切提交、源码树、依赖、迁移版本、测试数、JAR SHA-256及前端产物树SHA-256，并记录两份构建是否一致。该外部清单避免把开发期工作树的测试结果误认成另一提交的验收结果；发布时保留经过审查的public清单和对应产物，原始日志及浏览器配置留在忽略目录。

当前验证环境为Windows、Java17、Node20、MySQL8、Redis及本机Chrome，支持单应用实例。没有在本轮执行校园生产升级、学校官方身份系统接入、多实例交付或校园数据量容量认证；此前聊天P2容量与历史发布记录继续按各自绑定版本解释。
